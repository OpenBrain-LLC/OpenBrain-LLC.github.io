Introducing Agent-0

A CLI agent that runs on your machine. Here's what it does, how it's built, and where it falls short.

October 2026 · OpenBrain-LLC · 12 min read

Agent-0 is a command-line AI agent. You start it in a terminal, type at it, and it responds. It has five tools it can call: run a shell command, search the web, fetch a URL, and two ways to write to a memory file. It keeps notes between sessions, and it can work on a goal in the background while you do something else.

It runs on your own hardware by default.

What Agent-0 is

The name and premise come from the Agent-0 in AI-2027. That version is fictional. This is the version you can install. We kept the name because the framing — a small, inspectable agent that runs locally — is the part we wanted to build.

It's a single Python file. You start it, it loads a model, and you get a prompt. You type a request, it decides whether to answer directly or call a tool, and it shows you what it's doing. When it's finished, it prints the result and waits for the next thing.

Why local-first

Most agents send everything to a hosted API. That works well for a lot of use cases. It's a problem when you want the agent to read your files, run commands on your machine, or remember things across sessions.

Agent-0 defaults to Ollama, which runs models locally. Your prompts, your files, and your notes stay on your machine. If you want to use Groq instead, you can, and the agent will tell you when it's leaving your machine.

The tradeoff is speed. A 1.5B model on a laptop is slower and less capable than a frontier model running on a data center GPU. We think local is the right default for this kind of tool, and we make it easy to switch when you want to.

Installing it

You need Python 3.10 or later. Clone the repository and run the app script: 

git clone https://github.com/OpenBrain-LLC/Agent-0
cd Agent-0
./app.sh

The script refuses to start if stdin isn't a TTY. That's deliberate. The agent asks for input, and piping it from a script doesn't match how it's meant to be used.

On first launch, defaults are written into db/local/.

The two backends

Ollama

Ollama is the default. It runs models locally and doesn't need an API key. The default model is deepseek-r1:1.5b.

That model is tiny, and it will fumble tool calls. Switch to something larger as soon as you can. Use the /model command in the REPL, or edit the config file directly. If ollama list shows a model, /model will accept it.

Groq

Groq runs models on their hardware. It's much faster than local inference on a laptop. It needs an API key.

From the REPL: 

/api gsk_your_key_here

That saves the key with file mode 600 and switches you to the Groq backend in one step. You can also set AGENT0_GROQ_API_KEY in your environment, which takes precedence over the stored key.

The five tools

Agent-0 has five tools. The list isn't extensible at runtime, and that's intentional. Fewer tools means less surface area to reason about on every turn.

shell

Runs a command through /bin/sh with a 60-second timeout.

This is the only tool that can do real damage, so it always asks for confirmation. Every single time. No autonomy level changes this.

There are guardrails against patterns like rm -rf /, fork bombs, dd of=/dev/..., mkfs, force-pushing to main, and curl | bash. They're regex-based. They will catch obvious mistakes and miss creative ones.

web_search

DuckDuckGo search. Returns titles, URLs, and snippets.

fetch_url

A plain GET request with a roughly 500 KB cap. HTTP and HTTPS only. It doesn't execute JavaScript, so pages that render client-side will come back mostly empty.

memory_append

Adds a bullet to a named section in memory.md. Creates the section if it doesn't exist.

memory_write

Replaces the entire memory file. You almost never want this. It exists because sometimes you do.

Autonomy levels

There are four levels, set with /auto:

  • manual — asks for everything
  • smart — asks for everything
  • auto — auto-approves the web and memory tools; shell still asks
  • yolo — same as auto in practice; shows a warning

We intended these to be three distinct tiers: safe, medium, and dangerous. What actually shipped is different. The _autonomy_ok function only checks one flag, and manual and smart behave identically. yolo doesn't unlock anything that auto doesn't already have.

We know. It's on the roadmap.

Memory and sessions

Notes live in memory.md. The agent can append to sections or rewrite the whole file.

Sessions are saved as JSON. Right now there's no way to list or resume them from the CLI. They're on disk, but you'd have to find them yourself. That's a gap we want to close.

Goals

You can hand the agent a goal with /goal and let it work in the background. Separate budgets apply for steps, tool calls, and wall time, so it can't run forever.

Between turns, a critic call decides whether the goal is DONE, should CONTINUE, or is STUCK. This is a simple mechanism and it sometimes gets the call wrong.

Design decisions

A few things we chose on purpose.

One file. Agent-0 is a single Python script. You can read the whole thing in an afternoon. This makes it easy to audit and easy to fork. It also means it doesn't scale to a large feature set, which we accept.

No daemon. There's nothing running in the background when you're not using it. When you close the terminal, it's gone.

Five tools. Adding a sixth tool means the model has more to reason about on every turn. We'd rather make five tools work well.

Shell asks. A shell command can delete your files. The agent should never run one without you knowing.

Known limitations

The default model is bad at tool calls. You should change it.

The autonomy levels don't match their names. manual and smart are the same, and yolo is a warning label rather than a mode.

There's no session browser. If you want to resume an old session, you'll need to find the JSON yourself.

The guardrails are regexes. They'll catch common dangerous patterns and miss anything unusual.

What's next

The roadmap lists current priorities. It's short, and we'd rather keep it that way than promise more than we can build.

The code is at github.com/OpenBrain-LLC/Agent-0. Issues and pull requests are welcome.
