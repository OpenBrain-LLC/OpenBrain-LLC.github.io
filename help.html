Help

Setup and common questions.

Install steps, backend choices, the five tools, and what the agent will do on its own.

Getting started

How do I install Agent-0?

Clone the repository and run app.sh. You'll need Python 3.10 or later.

git clone https://github.com/OpenBrain-LLC/Agent-0
cd Agent-0
./app.sh

The script refuses to run if stdin isn't a TTY, because half the interaction is input() prompts.

On first launch, defaults are written into db/local/. Ollama is the default backend.

Which model should I use?

The default model has been updated to one that calls all five tools reliably. Earlier builds defaulted to deepseek-r1:1.5b, which fumbled tool calls — that's no longer the default.

You can still switch any time. Use /model in the REPL, or edit the config directly. If ollama list shows a model, /model will take it.

Rule of thumb: bigger models handle multi-step tool use better, but they're slower locally. Try a few and see what your machine tolerates.

How does the Groq backend work?

From the REPL, run /api gsk_... with your key. That saves the key with mode 600 and switches you to Groq in one step.

You can also set AGENT0_GROQ_API_KEY in your environment. That wins over the stored key, which is handy for CI or shared machines.

Groq is much faster than local inference on a laptop, but it means your prompts leave your machine. The agent tells you when it's using a remote backend.

What does it write to disk?

Three things: memory.md for notes, JSON files for session history, and a config file under db/local/ created on first launch.

Nothing is written outside the project directory, and there's no background process left running after you close the terminal.

Tools and autonomy

What tools does Agent-0 have?

Five: shell, web_search, fetch_url, memory_append, and memory_write.

The list isn't extensible at runtime and isn't meant to be. There's no dedicated file-reading tool — if you want the agent to look at a file, it uses shell with cat, head, or grep.

A plugin system for registering custom tools is on the roadmap.

Will it run shell commands on its own?

Not by default. Shell requires [Y]es/[N]o confirmation unless you explicitly switch to yolo.

There are guardrails for rm -rf /, fork bombs, dd of=/dev/..., mkfs, force-pushing to main, and curl | bash. They're regexes, so they'll catch obvious mistakes and miss creative ones.

A test suite for the guardrails is in progress — it covers every pattern they claim to catch.

What are the autonomy levels?

Three distinct tiers, set with /auto:

  • manual — safe: asks for every tool call
  • smart and auto — medium: auto-approves the web and memory tools; shell still asks
  • yolo — dangerous: auto-approves shell too, with a warning

This split now works as intended. Earlier builds treated manual and smart identically and yolo didn't unlock anything new — that's been fixed.

If you don't need background tool use, stay on manual. yolo is there when you mean it, not as a default.

Memory, sessions, and goals

Where do notes and sessions go?

Notes live in memory.md. Sessions are saved as JSON next to it.

memory_append adds a bullet to a named section and creates it if needed. memory_write replaces the whole file — you almost never want that.

How do I resume an old session?

Sessions are saved as JSON, but there's no CLI list or resume flow yet. You can inspect the JSON directly.

agent0 sessions is in progress and will let you list and resume from the CLI. It's marked "Now" on the roadmap.

How do goals work?

Hand the agent a goal with /goal and it works in the background. Separate budgets apply for steps, tool calls, and wall time, so it can't run forever.

Between turns, a critic call decides whether the goal is DONE, should CONTINUE, or is STUCK. It's a simple mechanism and sometimes gets the call wrong — if you see it looping, stop it and rephrase.

Troubleshooting

The agent keeps fumbling tool calls. What do I do?

First, check you're on the updated default. If you manually set a small model, switch to something larger with /model.

Second, simplify the request. Multi-step instructions with several tool calls are much harder for small models than a single clear task.

Third, if it's still failing, open an issue with the model name and the prompt — that's exactly the feedback we use to pick defaults.

app.sh won't start. Why?

The most common cause is stdin not being a TTY — running it through a pipe or a non-interactive script will fail on purpose. Run it directly in a terminal.

If Python is the problem, check python3 --version. You need 3.10 or later.

Where can I report a bug?

Open an issue on the Agent-0 repository.

Include your OS, Python version, the model you were using, and the command that failed. That's usually enough for us to reproduce it.

Still stuck?

Open an issue and describe what you tried. Include your OS and Python version.
